# Этап 1: общие предохранители риска — готово

## Что добавлено

1. **`risk_guard.py`** (новый модуль) — три предохранителя поверх риска отдельной сделки:
   - максимум одновременно открытых позиций (across всех символов);
   - дневной лимит убытка в % от баланса на начало UTC-дня;
   - серия убыточных сделок подряд (считается по факту закрытия на бирже, `income` с `incomeType=REALIZED_PNL`, а не по локальному логу — так что сделка, закрытая вручную на сайте биржи, тоже учитывается).

2. **Kill switch.** Если сработал лимит убытка ИЛИ серия подряд — взводится персистентный флаг в `bot_state.db` (`queue_manager.set_kill_switch`), который **блокирует вообще все новые позиции** и **не снимается сам** — ни на следующий день, ни при следующей прибыльной сделке. Снять можно только осознанно:
   ```
   python3 risk_guard_cli.py status   # посмотреть, что случилось
   python3 risk_guard_cli.py reset    # снять (с подтверждением)
   ```
   Лимит "открытых позиций" — не kill switch, самоустраняется, когда одна из позиций закроется.

3. **Интеграция:** `futures_executor.open_protected_position` теперь принимает опциональный параметр `risk_limits` (`risk_guard.RiskLimits`) и, если он передан, проверяет все три лимита **первым делом — до единого вызова на изменение чего-либо на бирже** (до `set_leverage`). Отказ гарантирует, что позиция вообще не откроется.

   Параметр опционален (по умолчанию `None`) только ради обратной совместимости со старыми юнит-тестами — `futures_testnet_demo.py` (реальный вход) теперь **всегда** передаёт его из `config.py`. Любой будущий код, который будет открывать позиции (в т.ч. автоматический вход по сигналу из `scanner.py` — следующий этап) должен делать так же.

4. **Новые настройки** (`config.py` / `.env.example`, все с безопасными дефолтами):
   - `BINANCE_FUTURES_MAX_OPEN_POSITIONS` (по умолчанию 3)
   - `BINANCE_FUTURES_MAX_DAILY_LOSS_PCT` (по умолчанию 5.0)
   - `BINANCE_FUTURES_MAX_CONSECUTIVE_LOSSES` (по умолчанию 3)

5. **Новые методы `FuturesClient`**: `get_all_positions()`, `get_wallet_balance()`, `get_income_history()` — понадобились только `risk_guard.py`.

## О чём стоит подумать перед следующим этапом (авто-вход по сигналу)

- **Дневной baseline** фиксируется при ПЕРВОЙ проверке за UTC-день — если бот уже успел просесть до первого запуска в этот день, baseline будет ниже реального "начала дня". На практике для этого проекта (CLI запускается вручную) это некритично, но если появится cron-джоба, стоит держать это в уме.
- **Порядок проверок** внутри `check_new_position_allowed`: kill switch → открытые позиции → дневной убыток → серия подряд. Первые две — дешёвые (без сети или один вызов), последние две требуют реальных API-вызовов — так что при взведённом kill switch вообще ни один метод биржи не вызывается.
